# OfficeBridge

클라이언트리스 제로트러스트 게이트웨이 프로토타입 — VPN 설치 없이 브라우저만으로,
인가된 사내 시스템에만 접근할 수 있게 하는 릴레이+커넥터 구조입니다.

지란지교 해커톤 STEP 2 MVP 제출용 저장소입니다.

## 아키텍처

```
[브라우저] --HTTPS--> [릴레이 서버] --아웃바운드 WSS 터널--> [커넥터] --사내망--> [내부 시스템]
                          |
                    인증 · 정책 · 행위기반 검증 · 감사로그
```

- **릴레이 서버** (`relay/`): 사용자 인증(회사코드+이메일+비밀번호), MFA(TOTP), 부서/개인별 접근 정책,
  행위 기반 지속 검증(업무시간외 차단·요청빈도 제한·세션 IP 고정·로그인 잠금·세션 수명 제한), 감사로그,
  관리자 콘솔(조직도·정책·계정통제·로그·설치파일)을 담당합니다.
  **인바운드 포트를 사내망 쪽으로 열지 않습니다** — 커넥터가 먼저 아웃바운드로 붙습니다.
- **커넥터 앱** (`connector-app/`): 사내망 안에서 도는 로그인 게이트형 데스크톱 앱(Electron, Windows/Mac).
  관리자가 회사코드+계정(+MFA)으로 로그인해야 터널이 시작되고, 로그아웃하면 즉시 중단됩니다. 실제 내부
  시스템 주소·on/off 상태를 갖고 있는 유일한 주체입니다.
- **브릿지 앱** (`agent-bridge-app/`): 임직원용 데스크톱 앱(Electron, Windows/Mac). 회사코드+계정으로 최초
  1회만 인증하면 개인 브릿지 토큰을 받고, 그 뒤로는 로그인 없이 본인이 접근 가능한 시스템을 클릭 한 번으로
  엽니다. 관리자가 [조직도]에서 "접근 회수"를 누르면 다음 폴링 주기 내에 앱이 자동 로그아웃됩니다.
- **레거시 커넥터/메뉴바 앱** (`connector/`, `menubar-app/`): 초기 프로토타입 단계의 상시구동(launchd) 방식
  커넥터입니다. 로그인 게이트형 `connector-app/`으로 대체되어 현재는 소스로만 남아있습니다.
- **mock-apps** (`mock-apps/`, `connector/mock-apps/`): 데모용 가짜 사내 시스템(ERP/GitLab/그룹웨어/회계).
  실제 배포에서는 진짜 사내 시스템(예: 사내 ERP, GitLab)의 내부주소를 커넥터에 등록합니다.

## 저장소 구성

```
officebridge/
  relay/              릴레이 서버 (인증/정책/행위기반검증/터널/조직도/관리콘솔)
  connector/          커넥터 (아웃바운드 터널 + 로컬 관리 웹) — 별도 README 있음
  menubar-app/        커넥터 운영자용 macOS 메뉴바 앱 (연결상태·서비스 확인, 클릭해서 열기)
  agent-bridge-app/   임직원 개인용 macOS 브릿지 앱 (F-11 — 로그인 없이 본인 시스템 바로 접속)
  launchd/            커넥터 상시구동용 launchd LaunchAgent 예시
  mock-apps/          릴레이와 같은 박스에서 도는 데모용 내부 시스템
  data/               정책/사용자/토큰 데이터 (data/seed/ 는 데모 리셋용 초기값)
  certs/              TLS 인증서 생성 스크립트 (개인키는 저장소에 포함하지 않음 — 직접 생성)
  scripts/            relay 기동/중지/데모리셋 스크립트
  docs/               MVP 접근 정보, 데모 영상 스크립트 등 제출 문서
```

## 빠른 실행

### 1. 릴레이 서버

```bash
cd officebridge
npm install
bash certs/gen-cert.sh          # 자체 서명 인증서 생성 (certs/cert.pem, key.pem)
sudo setcap cap_net_bind_service=+ep "$(command -v node)"   # 443 포트를 non-root로 bind
bash scripts/start.sh           # relay + mock-apps 기동
```

기본 도메인은 `<서비스명>.<릴레이 IP를 대시로 바꾼 값>.sslip.io` 형태의 sslip.io 와일드카드 DNS를
사용합니다 (예: 릴레이가 `10.52.249.21`이면 `portal.10-52-249-21.sslip.io`). `relay/config.js`의
`DOMAIN` 값을 실제 릴레이 IP에 맞게 바꿔주세요.

### 2. 커넥터

사내망 안의 아무 머신(또는 같은 박스)에서:

```bash
cd connector
npm install
node index.js
```

자세한 단계별 가이드는 [`connector/README.md`](connector/README.md) 참고.

### 3. 계정

데모 계정은 전부 제거하고 실서비스 초기 상태로 리셋했습니다. 최초 관리자 1명만 시드로 등록되어 있고,
그 뒤 조직도·정책·서비스·계정은 전부 관리자 콘솔에서 실제 사용하며 채워나가는 구조입니다. 회사코드는
`relay/config.js`의 `TENANT_NAME`으로 설정합니다.

## 구현된 기능 (P0)

- **F-1 터널링** — 커넥터 아웃바운드 전용 WSS 터널, 요청/응답 JSON 봉투 방식, 하트비트로 유실 감지
- **F-2 인증** — 이메일/비밀번호, 세션 쿠키, 로그인 실패 잠금
- **F-3 정책 엔진** — 부서 정책 ∪ 개인 추가 권한, 위반 시 사내망에 요청 자체가 도달하지 않음
- **F-4 행위 기반 지속 검증** — 업무시간외 차단 / 요청빈도 제한 / 세션 IP 고정 / 세션 최대수명
- **F-5 감사로그** — 로그인/접속/관리자 조작 전체 기록, 실시간 SSE 스트리밍
- **F-6 관리자 콘솔** — 대시보드/조직도/사내시스템현황/정책접근관리/행위기반제어/세션계정통제/로그조회/설치파일
- **F-7 목업 앱** — 사내 시스템 4종 (ERP/GitLab/그룹웨어/회계)

## P0 이후 추가 구현

- **실제 사내 시스템 연동** — mock을 넘어 실제 ERP·GitLab 연동까지 확인 (HTTPS 백엔드 지원, 리다이렉트
  도메인 재작성, 자체서명 인증서 처리, 세션 쿠키 처리)
- **F-11 개인 브릿지 (Agent Bridge)** — 임직원용 데스크톱 앱. 회사코드 + 조직도 계정으로 앱에서 직접
  최초 1회 인증하면 개인 브릿지 토큰을 발급받고, 그 뒤로는 로그인 없이 본인이 접근 가능한 시스템을 클릭
  한 번으로 엽니다. 클릭마다 토큰을 세션으로 새로 교환하므로 로컬에 세션을 캐싱하거나 만료를 신경 쓸
  필요가 없고, 관리자가 "접근 회수"를 누르면 앱이 다음 폴링 주기 내에 자동 로그아웃됩니다.
- **로그인 게이트형 커넥터** — 상시구동 데몬 방식을 폐기하고, 관리자가 회사코드+계정으로 로그인해야만
  터널이 열리는 방식으로 전환. 로그인마다 개인화된 커넥터 토큰이 발급되고(재로그인 시 이전 토큰 자동
  무효화), 관리자 콘솔에서 "연결 강제 종료"로 즉시 끊을 수 있습니다.
- **2차 인증(MFA)** — Google Authenticator 호환 TOTP를 외부 라이브러리 없이 직접 구현. 커넥터 로그인은
  비밀번호 하나로 사내망 터널을 여는 고위험 동작이라, 계정별로 MFA를 필수로 지정할 수 있고 전체 계정
  일괄 필수화도 가능합니다. 등록 비밀키는 본인 화면에만 노출되고 관리자에게는 보이지 않습니다.
- **조직도 관리 고도화** — 회사→부서→임직원 트리 UI(아바타, 실시간 검색, 통계 타일), 부서/임직원 추가는
  모달 다이얼로그, 임직원 행의 톱니바퀴 메뉴로 수정(이름·이메일·부서 일괄 변경, 이메일 변경 시 토큰·정책
  권한 자동 이전)·삭제, 빈 부서 삭제. 정책접근관리·계정통제 페이지도 동일한 톤으로 통일.
- **관리자 프로필 셀프서비스** — 이름 변경, 비밀번호 변경(현재 비밀번호 확인)을 콘솔에서 직접 처리.
- **회사코드 로그인 게이트** — 포털 웹 로그인에 회사코드 입력란 추가, 향후 멀티테넌트 확장을 고려한 구조.
- **설치 파일 배포 페이지** — 브릿지 앱·커넥터 앱 모두 로그인 없이 공개 다운로드, Windows/Mac OS 플랫폼
  타일 UI로 통일. 두 앱 모두 Windows(win32/x64)·Mac(darwin/arm64) 빌드를 함께 제공합니다.

## 알려진 한계 / 다음 단계

- 세션·터널 상태가 인메모리 — 릴레이 재시작 시 웹 세션·커넥터 연결이 끊기고 재로그인이 필요 (P1: 영속
  스토리지 또는 무중단 재시작)
- Windows 빌드는 빌드 환경에 Wine이 없어 rcedit(아이콘/버전 메타데이터 주입) 단계를 건너뛰고 패키징함 —
  실행에는 문제없으나 파일 속성상 제품명·아이콘이 기본 Electron 값으로 표시됨. 두 앱 모두 코드사이닝이
  되어 있지 않아 macOS Gatekeeper·Windows SmartScreen 경고가 최초 실행 시 뜸(다운로드 페이지에 우회
  방법 안내 포함)
- 커넥터에서 삭제한 서비스가 릴레이 쪽에 "연결 안됨"으로 남음 — 삭제 전파 메시지 필요
- 현재는 단일 테넌트(회사코드 하나) 구조 — 멀티테넌트로 가려면 회사코드별 데이터 완전 분리 필요
- F-8(추가인증 확장) / F-9(AI 요약) / F-10(커넥터 모니터링 대시보드) 미착수
